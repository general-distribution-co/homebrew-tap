Command-line documentation

GENRL CLI

Install GENRL, sign in from your terminal, inspect live capacity and credits, purchase bounded on-demand compute, connect to it, and terminate it safely.

Start the quick guide Browse every command

Overview

The CLI uses the same authenticated workspace and live offer book as the GENRL wallet. Human output is formatted for terminals; stable JSON is available for scripts.

Interactive use

Readable by default

Tables, labeled summaries, confirmations, and safe access metadata are shown when output is attached to a terminal.

Automation

JSON when requested

Place --json before a command, or pipe output, to receive machine-readable API projections.

Commercial boundary

Plan first, purchase second

compute plan is read-only. compute create is the explicit billable boundary and places the maximum credit hold.

Safety

Confirmed, retry-safe actions

Purchases and termination require confirmation. Automation uses explicit spend ceilings and idempotency keys.

Live capacity can fail after planning. A plan is a time-limited quote, not a guarantee that a provider will accept the launch. Always inspect the operation if provisioning fails. Provider-account funding is separate from your GENRL wallet balance.

Install

Homebrew is the supported public installation path on macOS and Linux. The formula installs both genrl and genrl-mcp.

Requirements

  • macOS or Linux on Apple/ARM64 or Intel/AMD64 hardware.
  • Homebrew.
  • A modern browser for device login.
  • ssh for interactive VM or cluster connections.
  • jq only for the optional automation examples.

Install from the GENRL tap

brew install general-distribution-co/tap/genrl

command -v genrl
genrl --help
command -v genrl-mcp

Upgrade or reinstall

brew update
brew upgrade genrl

# If Homebrew reports the current version is already installed:
brew reinstall genrl

Resolve an older local binary

If which -a genrl lists $HOME/.local/bin/genrl before the Homebrew path, your shell may run an older manual build.

which -a genrl

# Apple Silicon Homebrew normally uses this path:
/opt/homebrew/bin/genrl --help

# Intel macOS and many Linux installs normally use:
/usr/local/bin/genrl --help

Remove or reorder only the obsolete entry you recognize. Do not delete a binary until you have confirmed its exact path.

Build from source

Repository collaborators with Go installed can build the current checkout:

mkdir -p "$HOME/.local/bin"
go build -o "$HOME/.local/bin/genrl" ./cmd/genrl
go build -o "$HOME/.local/bin/genrl-mcp" ./cmd/genrl-mcp
export PATH="$HOME/.local/bin:$PATH"

Quick start: launch a VM

This is the shortest interactive path. Review every returned price and provider before confirming because create is billable.

1

Sign in

genrl auth login \
  --api-url https://genrl-wallet-api-production.up.railway.app \
  --profile production

export GENRL_PROFILE=production
genrl auth status
2

Check account, credits, and VM offers

genrl account show
genrl credits balance
genrl offers list --kind vm --purchase-model on-demand

Copy an exact value from the OFFER column. An empty table is a successful response meaning no matching capacity is currently available.

3

Create a read-only plan

GENRL_OFFER_ID='off_replace_me'

genrl compute plan \
  --offer "$GENRL_OFFER_ID" \
  --kind vm \
  --name cli-test-vm \
  --on-demand \
  --max-hours 1 \
  --max-cost 1GCR

Copy the returned plan ID. Adjust the maximum cost to a ceiling you actually approve. Planning does not place a hold.

4

Purchase the plan

GENRL_PLAN_ID='plan_replace_me'

genrl compute create --plan-id "$GENRL_PLAN_ID"

The interactive CLI displays provider, rate, runtime, and maximum hold before asking Purchase this compute? [y/N]. Copy the operation ID and resource ID after confirming.

5

Wait, inspect, and connect

GENRL_OPERATION_ID='operation_replace_me'
GENRL_RESOURCE_ID='resource_replace_me'

genrl operations wait "$GENRL_OPERATION_ID"
genrl compute get "$GENRL_RESOURCE_ID"
genrl compute access "$GENRL_RESOURCE_ID"
genrl compute connect "$GENRL_RESOURCE_ID"
6

Terminate when finished

genrl compute delete "$GENRL_RESOURCE_ID" --reason 'work complete'

Confirm the prompt, copy the returned termination operation ID, and wait for completion.

GENRL_TERMINATE_OPERATION_ID='operation_replace_me'

genrl operations wait "$GENRL_TERMINATE_OPERATION_ID"
genrl compute get "$GENRL_RESOURCE_ID"
genrl credits balance

Authentication and profiles

Interactive credentials are stored in the operating-system credential store. Profile metadata selects the API and workspace without writing bearer credentials into the config file.

Browser/device login

genrl auth login \
  --api-url https://genrl-wallet-api-production.up.railway.app \
  --profile production

The CLI opens the GENRL device page, displays a short code, and waits for you to approve the requested workspace and scopes.

Native password login

genrl auth login \
  --password \
  --identifier you@example.com \
  --api-url https://genrl-wallet-api-production.up.railway.app \
  --profile production

The password is read from a hidden terminal prompt. It cannot be supplied as a command argument or environment variable.

Select and inspect a profile

export GENRL_PROFILE=production
genrl auth status

# Or inspect a profile without changing GENRL_PROFILE:
genrl auth status --profile production

A current login can show profile, API, user, workspace, scopes, expiration, and available credit information. Older sessions may need a fresh login to obtain the newer account:read and credits:read scopes.

Log out

genrl auth logout --profile production

Logout revokes the refresh family before removing local profile credentials. If the API cannot be reached, local credentials are retained so revocation can be retried safely.

Never paste passwords or tokens into command arguments. Shell history, process listings, terminal recordings, and support transcripts may preserve them. Use device login, the hidden password prompt, or a hidden environment-variable prompt.

Account, workspace, and credits

Account

genrl account show displays the authenticated user, email verification, workspace, and role.

Credits

genrl credits balance displays available, held, total, and spent GENRL credits.

Context

genrl context show displays the actor and workspace authority used for requests.

Capabilities

genrl capabilities displays what this server and credential currently permit.

genrl account show
genrl credits balance
genrl context show
genrl capabilities

Available credit can fund new holds. Held credit is reserved for active or pending compute. Spent is already captured usage. A provider can still reject provisioning if GENRL's provider account lacks funding even when your own GENRL balance is sufficient.

Providers and live offers

The catalog is workspace-scoped live capacity, not synthetic test inventory. Offer availability can change between discovery, planning, and provider launch.

genrl providers list
genrl providers get hyperstack

genrl offers list --purchase-model on-demand
genrl offers list --kind vm --purchase-model on-demand
genrl offers list --kind cluster --purchase-model on-demand
genrl offers list --kind container --purchase-model on-demand
genrl offers list --kind notebook --purchase-model on-demand
genrl offers list --kind service --purchase-model on-demand
KindPurposeTypical access
vmGeneral virtual machine capacity.SSH when a verified public method is ready.
clusterMultiple coordinated compute nodes.Provider/server-declared cluster access.
containerContainerized runtime capacity.Server-declared endpoint or runtime interface.
notebookInteractive notebook environment.Verified HTTPS URL through compute open.

An empty table is not an error. It means no currently purchasable offer matches that workspace, kind, and purchase model. Try again later or inspect another kind; do not substitute an invented offer ID.

Plan and start compute

Friendly on-demand plan

genrl compute plan \
  --offer off_replace_me \
  --kind notebook \
  --name research-notebook \
  --on-demand \
  --max-hours 2h30m \
  --max-cost 5GCR

--max-hours accepts a number of hours such as 2 or a Go-style duration such as 2h30m. --max-cost is an exact GCR ceiling. The plan records provider, region, resource specification, rate, estimated cost, maximum cost, and expiration.

API-shaped plan file

Use --file when the resource needs fields not exposed by the friendly form. This example is an on-demand notebook request:

{
  "offer_id": "off_replace_me",
  "purchase_model": "on_demand",
  "maximum_runtime_seconds": 3600,
  "maximum_amount_micros": 1000000,
  "spec": {
    "kind": "notebook",
    "name": "research-notebook",
    "ttl_seconds": 3600,
    "price_ceiling": {
      "amount_micros": 1000000,
      "currency": "GCR"
    },
    "notebook": {
      "image": "jupyter/base-notebook:latest",
      "machine_profile": "replace-with-offer-profile"
    }
  }
}
genrl compute plan --file compute-plan.json
genrl compute plan --file - < compute-plan.json

The API schema also recognizes reserved commercial terms, but the current friendly CLI and offer filter expose on-demand use. Treat reservation availability as server-gated and check genrl capabilities; do not assume a reserved request is purchasable merely because a JSON field is accepted.

Interactive purchase

genrl compute create --plan-id plan_replace_me

The local plan receipt supplies the exact maximum cost. The CLI shows a confirmation view and generates an idempotency key after approval.

Non-interactive purchase

GENRL_CREATE_KEY="create-$(date -u +%Y%m%dT%H%M%SZ)"

genrl compute create \
  --plan-id plan_replace_me \
  --max-cost 5GCR \
  --idempotency-key "$GENRL_CREATE_KEY" \
  --yes

The maximum cost must exactly match the persisted plan. If a network result is ambiguous, retry the same purchase with the same idempotency key. A different key represents a different purchase attempt.

What happens to the credit hold? Create places one hold for the plan maximum before the provider effect is dispatched. Successful termination captures final metered use and releases the unused remainder. A compensated provisioning failure releases the applicable hold; inspect the operation until it reaches a terminal state.

Inspect and access compute

genrl compute get resource_replace_me
genrl compute access resource_replace_me

compute get shows lifecycle and contract state. compute access shows only customer-safe, server-approved metadata and never prints credentials.

Connect to a VM or cluster

genrl compute connect resource_replace_me

This requires interactive stdin and stdout. The CLI verifies a public SSH method, asks for confirmation, consumes the one-time credential handoff, and launches the local ssh process. Use compute access first if the resource is still pending.

Open a notebook or service

genrl compute open resource_replace_me

The CLI opens only a server-declared, verified public HTTPS URL after confirmation. It will not open arbitrary provider metadata.

Unavailable access is expected while provisioning. If the resource is pending and access shows no methods, wait for its create operation. If the operation failed, access will not become ready; inspect the operation error instead.

Stop and delete compute

Interactive termination

genrl compute delete resource_replace_me --reason 'work complete'

The CLI fetches the resource, shows its provider and settlement state, and asks for confirmation before termination.

Non-interactive termination

GENRL_STOP_KEY="stop-$(date -u +%Y%m%dT%H%M%SZ)"

genrl compute delete resource_replace_me \
  --reason 'work complete' \
  --idempotency-key "$GENRL_STOP_KEY" \
  --yes

Reuse the same stop idempotency key if the response is ambiguous. On-demand metering continues until provider lease closure is confirmed, so wait for the termination operation rather than assuming the first request stopped billing.

Termination is destructive. Save required files and outputs first. Early reserved termination may be non-refundable under confirmed reservation terms.

Operations and failures

Launch and termination are asynchronous. The operation is the authoritative record of whether the requested effect succeeded, failed, was cancelled, expired, or required compensation.

genrl operations get operation_replace_me
genrl operations wait operation_replace_me

operations wait performs bounded polling. If its local wait limit is reached or you interrupt it, the remote operation continues. Resume safely with the same command.

StateMeaningNext action
Pending / queued / runningThe remote effect is still progressing.Wait again or inspect later.
Awaiting approvalThe server requires an approval not exposed by this CLI command.Use the approved platform workflow.
SucceededThe requested lifecycle effect completed.Inspect the resource or access metadata.
FailedThe provider or platform rejected the effect.Read the safe error code/message and request ID.
Compensation failedThe primary effect failed and cleanup also needs attention.Preserve IDs and contact GENRL support.
Cancelled / expiredThe operation will not continue.Create a fresh plan or request if still needed.

JSON, PATs, and automation

Machine-readable output

genrl --json account show
genrl --json credits balance
genrl --json offers list --kind vm
genrl --json compute get resource_replace_me

# Piped output is JSON as well:
genrl offers list | jq '.offers[] | select(.available)'

--json is a global flag and can appear before the command. Set NO_COLOR=1 to disable terminal color in human output.

Copy identifiers safely with jq

GENRL_OFFER_ID=$(genrl --json offers list --kind vm | jq -r '.offers[0].id')

PLAN_JSON=$(genrl --json compute plan \
  --offer "$GENRL_OFFER_ID" \
  --kind vm \
  --name automated-vm \
  --on-demand \
  --max-hours 1 \
  --max-cost 1GCR)

GENRL_PLAN_ID=$(printf '%s' "$PLAN_JSON" | jq -r '.plan.id')

CREATE_JSON=$(genrl --json compute create \
  --plan-id "$GENRL_PLAN_ID" \
  --max-cost 1GCR \
  --idempotency-key "create-$(date -u +%Y%m%dT%H%M%SZ)" \
  --yes)

GENRL_OPERATION_ID=$(printf '%s' "$CREATE_JSON" | jq -r '.operation.id')
GENRL_RESOURCE_ID=$(printf '%s' "$CREATE_JSON" | jq -r '.operation.resource_id')

PAT environment mode

CI and other non-interactive processes can bypass local profiles with a complete three-variable authority. Obtain a scoped PAT from GENRL and treat it as a secret shown only once.

export GENRL_API_URL='https://genrl-wallet-api-production.up.railway.app'
export GENRL_WORKSPACE_ID='wks_replace_me'
printf 'GENRL PAT (hidden): '
IFS= read -r -s GENRL_API_TOKEN
printf '\n'
export GENRL_API_TOKEN

genrl --json context show

All three variables must be set together. Environment authority overrides profiles and remains process-local. Remove it when finished:

unset GENRL_API_URL GENRL_API_TOKEN GENRL_WORKSPACE_ID

Local MCP server

Homebrew installs genrl-mcp, a local stdio MCP server that uses fixed API, token, and workspace authority supplied through its environment.

No hosted remote MCP URL is shipped today. The current MCP integration runs locally as a child process of your MCP client. Do not configure an invented HTTP endpoint.

Required environment

  • GENRL_API_URL — the HTTPS GENRL API base URL.
  • GENRL_API_TOKEN — a scoped PAT or supported bearer token.
  • GENRL_WORKSPACE_ID — the exact authorized workspace.

Generic stdio client configuration

{
  "mcpServers": {
    "genrl": {
      "command": "/opt/homebrew/bin/genrl-mcp",
      "env": {
        "GENRL_API_URL": "https://genrl-wallet-api-production.up.railway.app",
        "GENRL_API_TOKEN": "REPLACE_WITH_SCOPED_PAT",
        "GENRL_WORKSPACE_ID": "wks_replace_me"
      }
    }
  }
}

Use the actual result of command -v genrl-mcp for command. Store secrets using your MCP client's secret mechanism when it offers one; avoid committing this configuration with a real PAT.

Troubleshooting

Homebrew says GENRL is installed, but the output looks old

Run which -a genrl. Your shell uses the first result. Compare it with brew --prefix genrl and remove or reorder only a confirmed obsolete manual installation.

The browser says it could not verify the login request

Start a fresh genrl auth login and use the newly displayed code. Device codes expire and can be used only for the matching request. Confirm that the API URL is exactly the production HTTPS URL shown in this guide.

auth status does not show email or credits

The profile may predate the account and credit scopes. Log out and sign in again, then run genrl account show and genrl credits balance.

Offers returns an empty table

The request succeeded, but no capacity currently matches the selected kind and purchase model for your workspace. Try another kind or check later.

The resource is pending but the website reports provisioning failed

Use the create operation ID with genrl operations get or genrl operations wait. The operation is authoritative while resource projections may briefly lag. A provider error such as insufficient provider credit refers to GENRL's account at that cloud provider, not necessarily your GENRL wallet balance.

compute access shows no methods

The resource is not ready, its operation failed, or the provider has not supplied a verified customer-safe access route. Inspect both the resource and operation before retrying.

A wait command timed out or was interrupted

The remote operation continues. Resume using the same operation ID: genrl operations wait operation_replace_me.

A create or delete response was lost

Retry the same action with the exact same idempotency key. Do not generate a new key for the same intended purchase or termination.
